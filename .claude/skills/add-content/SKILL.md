# Правка контента

Весь контент живёт в `model`-сегментах entities (см. `docs/fsd.md`, раздел «Данные контента»). Компоненты контент не хардкодят.

## Где что лежит

| Контент | Файл |
|---|---|
| Курсы (название, цена, программа уроков, якорь) | `src/entities/course/model/courses.data.ts` |
| Преподаватели (имя, роль, биография, фото) | `src/entities/teacher/model/teachers.data.ts` |
| Отзывы | `src/entities/review/model/reviews.data.ts` |
| Сервисы экосистемы | `src/entities/ecosystem-service/…` — entity ещё НЕ создана, заведи через `/fsd-slice` при первом наполнении |
| Статистика доверия («450+», выпускники, %) | `src/entities/stat/model/stats.data.ts` |
| Навигация (меню, футер, ссылка на кабинет) | `src/shared/config/navigation.ts` |

Если файла ещё нет — создай entity через skill `fsd-slice` (типы в `model/types.ts`, данные отдельным файлом).

## Правила

1. **Только data-файлы.** Если для правки контента приходится менять SFC-шаблоны — это дефект архитектуры: сначала вынеси контент в данные, потом правь.
2. **Типы обязательны.** Новое поле → сначала в `model/types.ts`, потом в данные, потом (если нужно) в UI.
3. **Цены** — числом (`price: 30000`), форматирование (₽, разряды) — на стороне UI через общий форматтер в `shared/lib`.
4. **Изображения** — в `public/images/<entity>/` (каталог `public/` — в корне репозитория, НЕ в `src/`; создать при первом ассете), kebab-case имена; в данных — путь строкой.
5. **Якоря курсов** должны совпадать с ссылками навигации/футера (`#osnovy-ekosistemy` и т.п. — см. `docs/pages.md`).
6. После правки: `npm run typecheck` (битое поле ловится типами раньше), затем `npm run generate`.

## Перенос текста с референса/старого сайта

- Копировать дословно, не пересочинять; недостающее — запрашивать у заказчика.
- Типографика: кавычки-«ёлочки», тире «—», буква «ё» — как в источнике.
- Неразрывные пробелы (в числах «30 000», перед «₽») в TS-файлах — только ` `-эскейпом, сырой символ ловит `no-irregular-whitespace`.
