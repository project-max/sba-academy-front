# Обновление зависимостей

Политика: самые свежие **стабильные** версии (pre-release/RC не брать).

## Известные пины и связки (проверять при каждом обновлении)

| Пакет | Ограничение | Причина | Когда снять |
|---|---|---|---|
| `typescript` | `~6.0.3` (НЕ 7.x) | TS 7 — нативный Go-компилятор; vue-tsc построен на JS-API tsc | когда vue-tsc заявит поддержку TS 7 (читать release notes vue-tsc) |
| `steiger` + `@feature-sliced/steiger-plugin` | обновлять парой | steiger жёстко пинует версию плагина внутри | всегда актуально |
| `motion-v` | — | peer: `@vueuse/core >=10` — сверять при мажорах обоих | всегда актуально |
| `vue` / `vue-router` | мажоры диктует `nuxt` | Nuxt 4.5 требует vue ^3.5.40, vue-router ^5.2 | обновляются вместе с nuxt |
| Node | >=22.19 (engines) | требование Nuxt 4.5; локально Node 26 | при мажоре Nuxt перечитать engines |

## Процедура

1. `npm outdated` — снять картину.
2. Мажоры Nuxt/Vue — сначала читать migration guide и требования к Node.
3. Обновить: `npm install <pkg>@latest …` (с учётом пинов выше).
4. Полная проверка: `npm run check` (postinstall сам прогонит `nuxi prepare`).
5. Если ESLint-плагины сменили API (как boundaries v6→v7: `element-types`→`dependencies`, `rules`→`policies`) — мигрировать конфиг сразу, депрекейты не копить.
6. Коммит `chore(deps): …` отдельно от прочих изменений — через skill `/commit`.
