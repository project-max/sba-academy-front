# SBA Academy — новая версия лендинга

Новая версия сайта [academysba.pro](https://academysba.pro/) (образовательная платформа: криптовалюты, блокчейн, партнёрский бизнес). Референс дизайна и структуры: https://sbaacademy.vercel.app/ (не финален — SCSS-переменные и дизайн-токены НЕ добавляем, пока дизайн не утверждён).

## Статус

Каркас развёрнут и проверен (lint / steiger / typecheck / generate — зелёные): 9 роутов, FSD-слои, entities с контентом курсов, форма-заглушка. Вёрстка секций — после утверждения дизайна (чек-лист в `docs/architecture.md`). Remote — Bitbucket (`bitteamdev/sba-academy`), CI при необходимости — Bitbucket Pipelines.

После клона: `npm install` (postinstall сам выполнит `nuxi prepare` — без него не работают lint и типы — и установит git-хуки).

## Принятые решения

- **Фреймворк:** Vue 3 + Nuxt 4, TypeScript. Зависимости всегда ставим самых свежих стабильных версий.
- **Рендеринг:** SSG (`nuxi generate` → чистая статика). Хостинг не выбран, поэтому никакой серверной логики: без nitro server routes в рантайме, формы шлют на внешний эндпоинт.
- **Архитектура:** Feature-Sliced Design. Слои в `src/`; роутинг Nuxt перенесён в `src/app/routes` (тонкие файлы), каноничный слой `pages` — за FSD. Правила и ESLint-контроль — `docs/fsd.md`. Нарушения границ слоёв недопустимы.
- **Auto-imports Nuxt отключены** — только явные импорты через публичные API слайсов (иначе boundaries-линт слеп). Composables Nuxt импортируются из `#imports`.
- **Стили:** SCSS, `<style lang="scss" scoped>` в SFC. **Цветовые токены заведены** — CSS custom properties в `src/app/styles/_colors.scss`; в компонентах только `var(--токен)`, сырые hex запрещены. Для темозависимых свойств — семантические токены (surface-*/text-*/border-*), палитра (brand-*/accent-*) — для декоративных брендовых элементов. Каркас тёмной темы заложен (`theme-dark` + `data-theme`/`prefers-color-scheme` — закомментированы до появления тёмных значений в дизайне). **Типографика заведена** — шрифт Onest (self-host через @nuxt/fonts), шкала — глобальные классы `_typography.scss` (`display-xl`…`label-s`): тег по семантике, класс по шкале, произвольные font-size/weight запрещены. Layout: фон `surface-page`; **контейнерная система** — весь контент в глобальном классе `.container` (max 1440px + padding-inline 64px, контентная область 1312px; `_layout.scss`): класс на корне секции, внутренности `width: 100%`. Брейкпоинты определим сами на этапе адаптива (до этого медиазапросы не писать; мобильные поля = правка `.container` в одном месте); z-index/мобильная шкала — по мере необходимости.
- **Контент** (курсы, преподаватели, отзывы, статистика) — только в типизированных data-файлах внутри `model`-сегментов entities, никогда не хардкодится в шаблонах.
- **Формы:** отправка через абстрактный слой `shared/api` — конечная точка (бэкенд/CRM/Telegram) ещё не выбрана.
- **Анимации:** CSS-first (hover/якоря/аккордеоны — без JS); JS-анимации — **motion-v** (официальный Motion для Vue) + встроенный `<Transition>`; слайдеры — embla-carousel-vue. Подробности: `docs/architecture.md` → «Анимации и интерактив».
- **Локализация:** отложена (RU-only); план миграции на @nuxtjs/i18n — `docs/architecture.md`. Крупные тексты держать в data-файлах — это условие дешёвой миграции.

## Открытые вопросы (не решены заказчиком)

- Хостинг продакшена (российский VPS vs облако) → пока строго статика.
- CMS для контента (пока — файлы в репозитории).
- Куда уходят заявки из форм.
- Мультиязычность («возможно позже») — до решения не тащим i18n-библиотеки.

## Команды

- `npm run dev` — dev-сервер
- `npm run generate` — SSG-сборка (итог в `.output/public`)
- `npm run lint` / `npm run lint:fsd` — ESLint (boundaries) / Steiger
- `npm run typecheck` — vue-tsc через nuxi
- `npm run check` — всё разом (гонять перед коммитом)

## Документация

- `docs/architecture.md` — решения, обоснования, план скаффолдинга.
- `docs/fsd.md` — слои, правила импортов, ESLint-конфиг, маппинг UI-блоков на слайсы.
- `docs/pages.md` — инвентаризация страниц и секций (что готово на референсе, что нет).

## Skills проекта

- `/fsd-slice` — создать слайс (entity/feature/widget/page) по правилам FSD.
- `/fsd-page` — создать новую страницу (роут в `src/app/routes` + page-слайс).
- `/add-content` — добавить/изменить контент (курс, преподавателя, отзыв) в data-файлах.
- `/landing-section` — сверстать секцию по макету (основная задача после прихода дизайна).
- `/commit` — git-коммит: Conventional Commits, английский, **без упоминаний ИИ** (дублируется commit-msg-хуком).
- `/pre-release` — чек-лист перед деплоем (блокер: заглушка `shared/api`).
- `/deps-update` — обновление зависимостей (политика latest + известные пины, в т.ч. typescript ~6.x).

## Соглашения

- Имена слайсов, файлов и компонентов-файлов — kebab-case (`course-card`, `submit-application`).
- SFC: `<script setup lang="ts">`, именованные экспорты из `index.ts` слайса.
- Импорт между слайсами — только через публичный API (`index.ts`) и алиас `@/` (= `src/`).
- Язык контента — русский (`lang="ru"`); мультиязычность отложена, см. план в `docs/architecture.md`.
- Коммиты — на английском, осмысленные (`feat:`, `fix:`, `docs:`, `chore:`).
