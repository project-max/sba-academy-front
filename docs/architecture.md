# Архитектура

## Контекст

Маркетинговый сайт академии: ~9 страниц, редкие изменения контента, без авторизации (личный кабинет — отдельный сервис `cabinet.academysba.pro`). Старая версия — самописный сайт с PHP-эндпоинтами (`rating.php`). Референс новой версии — sbaacademy.vercel.app (только визуальный ориентир, его кода у нас нет).

## Фреймворк: Vue 3 + Nuxt 4

Выбор заказчика (2026-08-05): команде ближе Vue. Для лендинга такого масштаба возможности Nuxt и Next эквивалентны; решает удобство поддержки. Зависимости всегда ставим самых свежих стабильных версий (учитывая peer-совместимость — см. заметки в исследованиях).

## SSG vs SSR — выбран SSG

| Критерий | Вывод |
|---|---|
| Контент | Статичен, меняется редко — пересборка при изменениях достаточна |
| Персонализация | Нет (кабинет — отдельный поддомен) |
| SEO | SSG закрывает полностью, TTFB лучше чем у SSR |
| Формы | Клиентский POST на внешний API, сервер рендеринга не нужен |
| Стоимость | Статику раздаёт любой nginx, Node-процесс не нужен |

SSR/гибрид понадобится только если появится живая динамика (рейтинг в реальном времени, цены из API). Nuxt позволяет перейти на гибридный рендеринг (route rules) без смены архитектуры.

## Ограничение: чистая статика

Хостинг не выбран (российский VPS vs облако). У Vercel и аналогов есть риски ограничений для РФ, поэтому до решения вопроса проект обязан собираться через `nuxi generate` в полностью статический вид (`.output/public` → любой nginx):

1. **Никаких nitro server routes в рантайме.** Формы шлют запросы на внешний эндпоинт через `shared/api`.
2. **Полный пререндер всех роутов** — `nitro.prerender.crawlLinks: true` обходит все внутренние ссылки.
3. **Изображения** — обычные `<img>`/`<picture>` с пре-оптимизацией на этапе сборки, либо `@nuxt/image` в static-режиме (генерация вариантов при билде). Решаем при появлении дизайна и реальных ассетов.

Если в итоге выберут облако с Node — ограничения просто снимаются, ничего переделывать не придётся. Обратное потребовало бы переделки.

## Контент-слой

CMS не выбрана, редактор контента неизвестен. Поэтому:

- Весь контент — в типизированных data-файлах в `model`-сегментах entities (`entities/course/model/courses.data.ts` и т.п.).
- Компоненты получают контент через пропсы/импорт публичного API entity — **не** хардкодят тексты.
- Если позже появится headless CMS — заменяется только источник данных в `model`, компоненты не трогаются.

## Отправка форм

Конечная точка не выбрана (кандидаты: существующий PHP-бэкенд SBA, Telegram-бот, email, CRM). Поэтому в `shared/api` — единственная функция вида `submitApplication(payload): Promise<Result>`, реализация за конфигом. Вся остальная кодовая база от выбора не зависит.

## Анимации и интерактив (по исследованию 2026-08-05)

Принцип: **CSS-first, JS — точечно**. Всё совместимо со статикой, обязательна поддержка `prefers-reduced-motion`, анимируем только `transform`/`opacity`, reveal — однократный (`once`).

| Задача | Решение |
|---|---|
| Hover карточек/кнопок | Чистый CSS (`transition`) |
| Плавные якоря | `scroll-behavior: smooth` + `scroll-margin-top` (без JS) |
| Появление бургер-меню | CSS `@starting-style` + transition; выход — `<Transition>` Vue |
| Аккордеоны программ | Нативный `<details name>`/`<summary>` + SCSS (`::details-content`; `interpolate-size` как progressive enhancement) — ноль JS, SEO-контент в DOM |
| Слайдер преподавателей | `embla-carousel-vue` (headless, ~8 KB gzip, стили наши) — Swiper отклонён (тяжёлый, web-component неудобен в SSG), keen-slider заброшен |
| Auto-hide хедера (скролл вниз — спрятать, вверх — показать) | Headroom-паттерн (решение 2026-08-12): sticky-хедер + `useAutoHide` из `shared/lib` (@vueuse/core; offset 96px, гистерезис 12px, кламп scrollY против iOS-резинки) — JS отдаёт только булево, анимация CSS `translate` 250ms; `:focus-within` раскрывает для клавиатуры, reduced-motion убирает transition, `scroll-padding-top` на html. Чистый CSS `scroll-state(scrolled)` отклонён: Chromium-only (~70%, не Baseline), без гистерезиса; пересмотреть, когда станет Baseline |
| Видео-трейлеры | Нативный `<video poster preload="metadata">`; для YouTube — паттерн «фасад» (iframe по клику) |
| Scroll-reveal секций, стаггер карточек, выезд меню | **motion-v** (официальный Motion для Vue, решение 2026-08-05): `whileInView` + `viewport.once`, стаггер через variants, AnimatePresence. Требует peer `@vueuse/core`. Простые enter/leave — встроенный `<Transition>` Vue. GSAP отклонён: с 2025 бесплатен, но ~40 KB императивного кода избыточны для reveal/stagger; вернуться к нему — только если дизайн потребует pin/scrub-хореографии |

Примитивы кладём в `shared/ui`: `carousel` (обёртка Embla), `accordion` (серверный, details/summary), `video-player`. Специфика — в widgets поверх данных entities.

## Базовый layout (обновлено 2026-08-12)

- Фон страницы — `var(--surface-page)` (задан на body и на `.layout`).
- **Контейнерная система** (`src/app/styles/_layout.scss`): весь контент — хедер, футер, секции — живёт в глобальном классе `.container` = `max-width: 1440px` + `padding-inline: 64px` + центрирование. Контентная область — **1312px** (border-box). Правило применения: `.container` на корне виджета-секции, внутренняя карточка/контент — `width: 100%`. Мобильный адаптив сведётся к правке `padding-inline` в одном месте.
- Секция с фоном во всю ширину экрана (если появится в макетах) — редкое исключение: корень без `.container`, класс ставится на внутреннюю обёртку.
- `main` — flex-колонка с `align-items: center`; `.container` имеет `width: 100%`, поэтому занимает всю ширину и центрирует содержимое полями.
- `min-height: 100dvh` (fallback `100vh`), футер прижат флексом.
- **Брейкпоинты** — из дизайна не придут: определяем сами на этапе адаптива, до этого в компонентах медиазапросы не писать.

## Тесты (решение 2026-08-05)

На этапе каркаса тесты **не заводим**: статичный лендинг почти без логики, smoke-контур дают typecheck + строгий `generate` (`prerender.failOnError`) — битая ссылка или упавшая страница валят сборку. Триггеры пересмотра: реализация настоящего `shared/api` (ретраи, маппинг ошибок) и валидация формы → точечный vitest; перед запуском — один Playwright-smoke по собранной статике. До этих триггеров вопрос не поднимать.

## Когда дизайн утверждён — чек-лист

Единый список, чтобы снять мораторий на токены синхронно во всех местах:

1. ✅ **Частично (цвета, 2026-08-11).** Токены — **CSS custom properties** в `src/app/styles/_colors.scss` (решение: не SCSS-`$переменные` — кастом-свойства работают в scoped-стилях без импортов и `additionalData`, видны в devtools; имена 1:1 с дизайн-документом, `border-subtitle` заведён как `border-subtle`). Двухуровневая структура под темизацию: палитра (brand-*/accent-* — примитивы вне тем) + семантические токены (surface-*/text-*/border-* через `@mixin theme-light`). **Каркас тёмной темы заложен**: при появлении её в дизайне — заполнить `theme-dark`, раскомментировать блоки `data-theme`/`prefers-color-scheme`, сменить `color-scheme` на `light dark`; компоненты не меняются. Осталось: типографика, брейкпоинты, z-index — по мере поступления дизайна.
2. ✅ Запрет «переменные не заводить» снят в части цветов (CLAUDE.md, docs/fsd.md, fsd-slice, global.scss). Новое правило: сырые hex в компонентах запрещены — только `var(--токен)`.
3. ✅ **Шрифты (2026-08-11).** Onest (в дизайн-документе «Onset» — такого шрифта не существует, сверено: набор начертаний совпадает; Google Fonts, SIL OFL, кириллица) через `@nuxt/fonts`: self-host на этапе сборки, веса 400–800 без курсивов, `subsets: ['cyrillic', 'latin']`, woff2, автоматический метрический fallback (size-adjust) против CLS. Шкала — глобальные классы в `_typography.scss` (`display-xl` … `label-s`, имена 1:1 с макетом): тег по семантике, класс по шкале; произвольные font-size/weight в компонентах запрещены. Мобильные размеры шкалы — когда появятся в макетах.
4. Принять `@nuxt/image` (static-режим: варианты генерируются при `nuxi generate`, рантайм не нужен) — правила: обязательные width/height, `format="avif,webp"`, lazy ниже первого экрана.
5. Заменить каркасные стили header/footer/error-page, брендовые favicon/og-image.

## Локализация (отложена — решение «возможно позже», 2026-08-05)

Сейчас сайт только на русском (`lang="ru"`), i18n-библиотек в проекте нет. Архитектура спроектирована так, чтобы миграция была дешёвой: крупные тексты живут в data-файлах entities/shared, не в компонентах.

План миграции на **@nuxtjs/i18n** (когда/если понадобится):

1. `@nuxtjs/i18n` в modules; `strategy: 'prefix_except_default'`, `defaultLocale: 'ru'` — русские URL не меняются, новые локали получают префикс (`/en/...`).
2. UI-строки каркаса (кнопки, подписи формы, aria) → словари vue-i18n (`locales/ru.json`, …).
3. Контент: data-файлы получают локале-варианты (`courses.data.ru.ts` / `courses.data.en.ts`), публичный API entity отдаёт данные по активной локали.
4. SEO (`hreflang`, canonical, локализованные роуты в SSG-пререндере) модуль делает автоматически.
5. Steiger/boundaries не затрагиваются — структура слоёв не меняется.

Оценка каркасных правок — ~1 день; основная стоимость — перевод контента. Compile-time альтернатива (Paraglide) рассмотрена и отклонена: адаптер для Nuxt менее зрел, а 95% наших текстов — контент-слой, которому библиотека i18n не помогает.

## Скаффолдинг

Требование к окружению: **Node 22.19+ / 24.11+** (Nuxt 4.5). Единственный намеренный пин — **typescript ~6.0.3**: latest 7.x — нативный Go-компилятор, vue-tsc построен на JS-API tsc; переход на TS 7 — отдельной задачей после проверки.

1. Зависимости (свежие стабильные, с учётом peer-совместимости из исследования).
2. FSD-каркас и ESLint/Steiger из `docs/fsd.md`; `nuxt.config.ts` уже настроен (srcDir, dir.pages, autoImport off, prerender).
3. Каркас страниц из `docs/pages.md` (тонкие роуты + пустые page-слайсы + layout с header/footer).
4. Entities с реальным контентом курсов, feature формы с заглушкой `shared/api`.
5. Проверка: `npm run check` (lint + steiger + typecheck + generate).
